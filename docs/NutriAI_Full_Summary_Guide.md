## 1. فكرة المشروع التسويقية (The Elevator Pitch)
* **المشكلة:** 90% من متبعي الحميات يعتمدون على معلومات عشوائية غير آمنة تؤذيهم (خاصة مع وجود أمراض كالسكري والضغط)، أو يعجزون عن دفع تكاليف المتابعة الدورية مع أخصائي التغذية.
* **الحل (NutriAI):** نظام ذكاء اصطناعي سريري تفاعلي يعمل كأخصائي تغذية علاجية في جيب المريض؛ يحسب احتياجاته بدقة طبية، ويبني خطة متكاملة لـ 15 يوماً، ويتفاعل معه عبر شات ذكي يعدل الجداول والتقرير لحظياً.

## 2. شرح واجهة الموقع بالتفصيل (زرار بزرار)

### أ. شاشة تسجيل الدخول وإنشاء الحساب (Authentication)
* **المكونات:** حقول اسم المستخدم، كلمة المرور، البريد الإلكتروني، زر الدخول، وزر إنشاء حساب.
* **الميزة الهندسية:** تعتمد على توثيق لا مركزي مشفر بنظام **JWT (JSON Web Tokens)** لعزل بيانات كل مريض وحمايتها.

### ب. الشريط الجانبي (Sidebar)
* **🌐 مبدل اللغة:** التبديل بين العربية (RTL مع قلب اتجاه الصفحة) والإنجليزية (LTR).
* **🎨 مبدل الثيم:** التبديل بين الوضع الداكن (Dark) والفاتح (Light) بألوان متناسقة ومريحة للعين.
* **🧠 محدد محرك الذكاء الاصطناعي:**
  * **⚡ محرك محلي بدون إنترنت (Offline):** أمان وخصوصية 100% بدون أي تكلفة أو إنترنت.
  * **سحابة Groq Cloud:** استجابة فائقة السرعة عبر نموذج **Llama 3.3 70B**.
  * **سحابة OpenRouter:** للتواصل مع أحدث النماذج العالمية.
* **➕ زر خطة جديدة:** لإعادة تعيين النموذج وبدء استبيان جديد.
* **🥗 قائمة الخطط السابقة:** كل خطة تحفظ في SQLite برقم فريد وتاريخ، وتسترجع بالكامل بضغطة زر.
* **🚪 زر تسجيل الخروج:** لإنهاء الجلسة بأمان.

### ج. استمارة الاستبيان الصحي (Clinical Form)
1. **البيانات الحيوية:** العمر والجنس (لحساب معدلات الأيض)، والوزن والطول (لحساب كتلة الجسم ومعدل الحرق الأساسي BMR).
2. **النشاط والهدف:** 5 مستويات نشاط لحساب الطاقة المستهلكة (TDEE)، و3 أهداف (خسارة دهون، تثبيت وزن، بناء عضلات).
3. **الملف المرضي المتقدم:** مربعات اختيار لأمراض (السكري Type-2، ضغط الدم، ارتفاع الكوليسترول، اضطرابات الغدة الدرقية).
4. **الحساسيات والنمط الغذائي:** حساسية اللاكتوز (حذف الألبان)، حساسية الجلوتين (حذف القمح والشعير)، حساسيات الأطعمة، واختيار نمط الأكل (متوازن، كيتو، نباتي، فيجان).
5. **زر توليد الخطة (Generate):** لبدء المعالجة واستخراج الـ 15 يوماً.

## 3. لوحة النتائج ومحرك الـ PDF

### أ. شريط الماكروز والقرارات الطبية
* **عدادات الماكروز الـ 4:** السعرات اليومية المحسوبة بـ Mifflin-St Jeor، وجرامات ونسب البروتين، النشويات المعقدة، والدهون الصحية.
* **صندوق التوجيهات الطبية (Medical Adjustments):** يوضح بالنقاط كيف تم تعديل الوجبات لحماية المريض حسب مرضه وحساسيته.

### ب. جداول الـ 15 يوماً التفاعلية
* معروضة بنظام كروت مزدوجة (2-Column Grid).
* كل يوم يضم 4 وجبات: **إفطار، غداء، عشاء، وسناك**.
* كل وجبة توضح المكونات بالجرام، وسعرات الوجبة، والشارة التفاعلية ✨ إذا طرأ أي تعديل.

### ج. زر تحميل التقرير الطبي المعتمد (PDF Export)
* يقوم بتوليد ملف A4 طبي رسمي للطباعة باستخدام مكتبة `ReportLab`.
* يدعم التشكيل والخطوط العربية من اليمين لليسار عبر `arabic-reshaper` و `python-bidi`.
* يحتوي على اسم المريض، تاريخ الإنشاء، الجداول الكاملة، وإخلاء المسؤولية الطبية السريرية.

## 4. الشات بوت التفاعلي والتحديث الحي (The Real-Time Engine)

* **فهم اللهجة المصرية والعامية:** يفهم التعبيرات الطبيعية (مثل: *"اليوم الاول ب اليوم التاني"* أو *"بدل الفراخ"* أو *"شيل البيض من الخطة"*).
* **التبديل المتبادل للأيام (Bilateral Day Swapping):** يبدل وجبات الأيام بالكامل متبادلاً في قاعدة البيانات.
* **الاستبدال الشامل للأطعمة (Global Substitution):** يستبدل المكون عبر الـ 15 يوماً مع إعادة احتساب السعرات.
* **التزامن الفوري:** تظهر رسالة منبثقة (Toast Notification)، وتتحدث الجداول وملف الـ PDF فوراً مع وضع شارة خضراء: `✨ تم التحديث بناءً على طلبك في الشات`.

## 5. تشريح الكود وهندسة الملفات والمكتبات

### هيكل المشروع (Architecture):
* **`backend/main.py`:** خادم REST API مبني بـ **FastAPI**، يحتوي على مسارات التوثيق، الخطط، والشات، ويوفر توثيق Swagger (`/docs`).
* **`backend/database.py`:** طبقة قاعدة بيانات **SQLite 3** علائقية تتضمن 3 جداول (`users`, `sessions`, `messages`).
* **`backend/providers/offline_provider.py`:** العقل المحلي للنظام؛ ينفذ معادلات **Mifflin-St Jeor** الطبية ومحلل النوايا بالعامية المصرية.
* **`backend/providers/groq_provider.py`:** عميل الاتصال السحابي السريع بنموذج **Llama 3.3 70B**.
* **`frontend/app.py`:** واجهة المستخدم التفاعلية المبنية بـ **Streamlit** مع إدارة كاملة للـ CSS والـ Session State.
* **`frontend/pdf_export.py`:** محرك توليد ملفات الـ PDF الطبية بالرسم والتشكيل العربي الصحيح.
* **`launch_nutriai.bat` و `NutriAI.exe`:** مشغلات بنقرة واحدة تستخدم مسارات نسبية (`%~dp0`) ليعمل البرنامج على أي جهاز فوراً.

### أهم المكتبات ولماذا تم اختيارها:
* **FastAPI:** أسرع إطار عمل بايثون مبني على `Async/Await` مع توثيق Swagger تلقائي.
* **Streamlit:** واجهة مستخدم تفاعلية وسريعة الاستجابة لتطبيقات الذكاء الاصطناعي.
* **Pydantic:** التحقق من أنواع وصحة البيانات المدخلة قبل معالجتها.
* **ReportLab + arabic-reshaper + python-bidi:** لإخراج تقارير PDF عربية رسمية بجودة طباعة عالية.

## 6. دورة حياة البيانات والذكاء الاصطناعي (Data & AI)

1. **مصادر البيانات (Data Sources):**
   * قاعدة بيانات وزارة الزراعة الأمريكية (**USDA FoodData Central**).
   * جداول **المعهد القومي للتغذية بمصر** لضبط الجرامات والأطعمة العربية.
   * الإرشادات السريرية لجمعيات السكري والقلب الأمريكية (**ADA & AHA**).
2. **التنظيف والمعالجة (Data Cleaning):**
   * تم في **Jupyter Notebook** باستخدام **Python (Pandas & NumPy)**.
   * إزالة التكرارات، توحيد الوحدات (جرامات لكل 100 جم)، تصنيف الأطعمة بمصفوفة أمان للحساسيات.
3. **حفظ البيانات (Data Persistence):**
   * محرك علائقي **SQLite 3** في `data/nutriai.db` عبر 3 جداول مرتبطة بـ Foreign Keys.
4. **طريقة عمل الذكاء الاصطناعي (Hybrid AI Strategy):**
   * **المحرك المحلي:** نظام خبير قطعي (Deterministic) لا يهلوس، يطبق معادلات Mifflin-St Jeor لحماية المريض بدون إنترنت.
   * **المحرك السحابي:** يعتمد على **Llama 3.3 70B** عبر تقنية **Clinical In-Context Learning & Strict JSON Prompting**.

## 7. أهم 5 أسئلة متوقعة من لجنة التحكيم وإجاباتها

1. **"لو الإنترنت فصل هل النظام هيتعطل؟"**  
   *الإجابة:* لا، لأن المحرك المحلي (Offline Engine) يعمل 100% بدون إنترنت بمعادلات بايثون وقاعدة بيانات SQLite مدمجة.
2. **"ما الفرق بينه وبين ChatGPT أو MyFitnessPal؟"**  
   *الإجابة:* MyFitnessPal مجرد عداد يدوي لما أكلته، وChatGPT يهلوس ولا يملك قاعدة بيانات. أما NutriAI فينظم الوجبات مسبقاً بناءً على الأمراض، ويغير جداول قاعدة البيانات والـ PDF لحظياً من الشات.
3. **"لو مريض سكر طلب حلويات من الشات، النظام هيتصرف إزاي؟"**  
   *الإجابة:* صمام الأمان الطبي يقرأ ملف المريض (`diabetes=True`) فيرفض السكريات البسيطة ويوجهه لبدائل منخفضة المؤشر الجلايسيمي كالشيكولاتة الداكنة +85% والمحليات الآمنة.
4. **"كيف تضمن عدم هبوط طاقة المريض أو خسارة عضلاته؟"**  
   *الإجابة:* نطبق عجز سعرات آمن (300-500 سعرة فقط)، مع تثبيت البروتين عند 1.6-2.0 جم/كجم وزن، ونشويات معقدة 45-50% ودهون صحية 25%.
5. **"ما هي خطتكم للتطوير المستقبلي؟"**  
   *الإجابة:* التعرف على الوجبات بالصور عبر الذكاء الاصطناعي (Computer Vision)، والربط مع الساعات الذكية (IoT) لقراءة الحرق الفعلي، وتطبيق هاتف بنظام Flutter مرتبط بنفس الـ API الحالي.
